## Reproduction environment

This host uses macOS arm64, Rust 1.99.1 and Homebrew FFmpeg 9. The release profile retains fat LTO.
These locally linked binaries are performance artifacts, not static distribution artifacts.

```sh
export PKG_CONFIG_PATH=/opt/homebrew/opt/ffmpeg/lib/pkgconfig
export RUSTFLAGS='-L native=/opt/homebrew/opt/lame/lib -L native=/opt/homebrew/opt/svt-av1/lib -L native=/opt/homebrew/opt/openssl@4/lib -l c++'
CARGO_TARGET_DIR=/tmp/remedia-hybrid-baseline cargo build --release --locked -p remedia-core \
  --example concurrent_playback_benchmark --example stream_output_benchmark
```

Use `benchmarks/playback.py` for codec concurrency and `stream_output_benchmark FILE FORMAT 3`
for streaming measurements. The latter includes Rust allocation instrumentation and must be
compared separately from uninstrumented timing. Native FFmpeg/libopus allocations are excluded.
Existing deterministic 60-second fixtures in `/tmp/remedia-audit-fixtures` are generated by the
repository fixture generator; no media-processing subprocess is used.

## Blocking audit

The single-source worker currently blocks in input opening/probing, demux/decode reads, seeks,
output readiness/writes/flush/finish, control acknowledgements and fallback promotion. The separate
crossfade worker also owns staged-source promotion and tail draining. File reads may block on the
filesystem; HTTP and byte streams may stall indefinitely until cancellation. Custom output methods
have a synchronous compatibility contract. None may be put wholesale into a shared CPU pool.

The first extraction retains decoder, processor, pending frame, filter update, seek recovery,
fallback state and active-playback guard in one persistent closure. Each invocation executes one
existing worker action. Paused playback yields to the dedicated driver, which checks the state
predicate under the session lock before sleeping, avoiding a notification race. Output and source
operations remain blocking at this milestone; this is not yet a scheduler-safe machine. Crossfade
continues on its original dedicated implementation.

## Evidence limits

Initial baseline codec and stream runs overlap some compilation and each other. They establish
release-mode harness operation and delivered-work counters, not precise small CPU differences.
An interleaved, isolated comparison is required for an adoption decision. No Linux constrained-CPU,
live Discord, native heap inventory or long-duration stability claim is made by these runs.
