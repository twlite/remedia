## Lazy encoded media

```ts
import { createReadStream } from 'node:fs';
import { createMediaSource, createPluginHost } from '@remedia/plugin-host';

const host = createPluginHost({ name: 'Media', publicUrl: 'https://plugins.example.com' });
host.register({
  id: 'example.media',
  operations: {
    stream: () =>
      createMediaSource({
        contentType: 'audio/ogg',
        open: ({ signal }) => createReadStream('/srv/media/example.ogg', { signal }),
        // Optional dispose(): release factory-owned resources, even if never opened.
      }),
  },
});
```

Return a fresh source per operation. Its `open({ signal })` returns a Node Readable or Web ReadableStream of Uint8Array encoded bytes, optionally through a promise. PCM objects and object-mode data are invalid. The factory must respect cancellation during asynchronous opening. A stream returned after cancellation is destroyed. `dispose()` runs once per HTTP grant after expiry, cancellation, failure or completion, including unopened grants. Keep resources inside the factory until opening succeeds. If opening throws before returning a stream, the factory must clean any partially created resources itself.

### Direct result ownership

For direct calls, the caller receives the exact source or stream and owns opening, cancellation, consumption and disposal after successful dispatch. A caller opening a source directly passes its own AbortSignal. The host destroys a stream returned by an operation that was cancelled before successful dispatch.

### HTTP grant ownership

For HTTP calls, streams and sources become `{ url, expiresAtMs }` descriptors. No source is opened until the media URL is redeemed. Eager streams are also supported but may buffer while waiting. Prefer lazy factories. Unredeemed tokens expire automatically. URLs use 256-bit random tokens, can be redeemed once, and remain tied to their registration during delivery. Expiration limits redemption time. It does not terminate an already redeemed stream. Streams use bounded transport buffering and are pulled by consumers. Producers must honor their stream implementation's backpressure.

Media is non-seekable. Range requests return 416 without consuming the token. The factory signature does not promise offsets, lengths or seek support. `remedia-server` honors this: it redeems each grant with one plain `GET` and decodes it as a forward-only stream (see [Playing audio through plugins](/docs/server/plugin-operations)). Seeking or reopening a single grant requires a separate, capability-negotiated contract which does not exist yet. A node whose guild opted in to [fallback seeking](/docs/server/plugin-operations#seeking-with-fallback-seeking) obtains a **new grant** by running the operation again, so a handler must be safe to run more than once for the same input.

### Server-side transfer

The server streams a redeemed response into the decoder through a bounded per-stream queue. When the decoder falls behind or pauses, the queue fills and the server stops pulling response chunks until the decoder catches up; it does not buffer the full media body. The transfer can also hold one current HTTP body chunk while waiting for queue space, and the HTTP client and decoder have their own buffers. `mediaBufferBytes` counts the visible bytes queued for the decoder; it is a backpressure limit, not a strict bound on total memory.

For this transfer, `reqwest::Response::chunk()` returns the HTTP body's `Bytes` data frame, which the server passes to `ByteStreamWriter::write_bytes` without first converting it to a `Vec`. A chunk that fits the queue avoids an extra ingress copy. `Bytes` does not expose its backing allocation size, so a small slice may retain more storage than its visible length. Producers using this core API should pass right-sized chunks when retaining a larger parent allocation would be costly. `maxMediaBytes` is checked against the declared length and again as chunks arrive. A stalled or interrupted response fails playback, and stopping or cancelling playback closes the transfer and releases its active-stream slot. See [plugin-host configuration](/docs/server/plugin-configuration) for the queue size and idle timeout.

Core byte-stream producers can pass a bytes::Bytes chunk to ByteStreamWriter::write_bytes. It blocks until a fitting chunk is accepted and returns the existing ByteStreamError cancellation, consumer-closure, or producer-termination errors.

```rust
writer.write_bytes(response_chunk)?;
```

Here, response_chunk is a bytes::Bytes value. A chunk that fits the queue is retained without an intermediate queue-ingress copy. The decoder still copies bytes into FFmpeg's input buffer. Chunks larger than the queue capacity are copied into bounded pieces, and a shared slice may keep its backing allocation alive until it is consumed.
