## Release authorization

The release workflow accepts an exact `chore: release x.y.z` or `chore: release x.y.z-tag.n`
commit on `main`, either through a push or a manual workflow dispatch for that commit.
Only repository collaborators with current **write**, **maintain**, or **admin** access may
release. Both the original workflow actor and the actor initiating a rerun must qualify.
Commit author names and emails do not grant permission.

CI verifies access through GitHub's repository permission API before marking a run as a release,
and again before changing tags or drafts, uploading assets, publishing npm packages, or making
the GitHub release public. Missing identities, insufficient access, and API failures block release
actions. Normal pushes, pull requests, and manual dispatches without a release commit continue to
run their existing checks. Releases remain restricted to `main`.

## Package publication

The release publisher verifies this package is present before publishing and reuses an
already published exact version when resuming an interrupted release. Configure npm Trusted
Publishing for `@remedia/plugin-host` with the same `twlite/remedia` repository and `ci.yaml`
workflow as the other release packages. Publishing uses npm OIDC Trusted Publishing.

## Static native artifacts and source

The existing platform workflow builds pinned GPL-enabled static FFmpeg 9, retains
all 13 addon targets, and packages server candidates for Windows ARM64 and Linux
x64/ARM64 musl in addition to the five original server targets. Windows ARM64 uses
an ARM64 runner; musl startup and addon decoding run in native-architecture Alpine
containers. Android and other cross targets remain provisional. ARMv7, Windows
x86 and FreeBSD server builds are investigated without publishing untested server
assets as supported releases.

A matching native dependency source bundle is required for every target. The
release packer combines these with the exact Remedia revision, release patch,
vendored Cargo dependencies, license inventory, configuration records and build
scripts into `corresponding-source.tar.gz`. Upload and finalization gates require
that archive alongside binary assets. FFmpeg configuration and dependency-license
allowlists fail closed on nonfree or unaudited additions; binary import checks
reject external FFmpeg, Opus and OpenSSL libraries. CI success does not establish
legal compliance. See [licensing](/docs/licensing).
