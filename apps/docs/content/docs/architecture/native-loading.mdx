---
title: Native loading
description: How the static native addon and server runtime load.
---

The engine addon statically links FFmpeg, including avfilter and resampling.
Importing `@remedia/node` loads the matching platform addon directly. Bootstrap
artifacts remain packaged for compatibility but no external FFmpeg is opened.
`getFfmpegRuntime()` reads identity from the compiled FFmpeg functions.

The administrative server CLI continues to launch the adjacent runtime executable.
The runtime bundles FFmpeg and requires no library search paths. Keeping this pair
preserves installer, updater, configuration and command behavior.

CI inspects ELF dynamic entries, Mach-O load commands and PE imports. External
FFmpeg, Opus and OpenSSL libraries are rejected. System C runtimes and OS frameworks
remain platform dependencies. Native runtime tests cover decoding, filtergraphs,
Opus output, seeking, crossfades and startup without FFmpeg provisioning.
See [distribution](/docs/node/distribution) for the target verification boundaries.
