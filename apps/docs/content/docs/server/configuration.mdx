# Server configuration

`remedia-server` loads a required JSON file from the current working directory. Override the path
with `--config PATH`. Unknown fields, missing required fields, invalid ranges, duplicate usernames,
and missing environment variables stop startup with an error.

```sh
cargo run -p remedia-server -- --config /etc/remedia/remedia.config.json
```

You can generate a safer starter file with `remedia-server --generate-config-file [PATH]`.
It will not overwrite existing files. For dotenv loading, diagnostic commands, and
running-instance discovery, see the [server CLI guide](/docs/server/cli).

```sh
remedia-server --generate-config-file
remedia-server --env-file .env --optional-env-file .env.remedia serve
remedia-server doctor --env-file .env
```

Use `--env-file` for a required file and `--optional-env-file` for a file which may
not exist. Both flags can be repeated. Required files load before optional files,
last matching assignment wins among files, and the already-exported environment
takes precedence over all file values. Empty and comment-only files are allowed;
malformed assignments are errors. These values are used only for JSON
`env('NAME')` references, not injected into process-global environment variables.

The full example file is [`remedia.config.example.json`](https://github.com/twlite/remedia/blob/main/crates/remedia-server/remedia.config.example.json).

## Schema

| Field                             | Type         | Default / validation                                                                                                  |
| --------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------- |
| `bind.host`                       | string       | `127.0.0.1`; must not be empty                                                                                        |
| `bind.port`                       | integer      | `8787`; valid `u16` port, `0` is available for ephemeral test binding                                                 |
| `users`                           | array        | Required and non-empty; usernames must be unique                                                                      |
| `users[].username`                | string       | 1–128 characters, cannot contain `:`                                                                                  |
| `users[].password`                | string       | Required; 1–4096 bytes                                                                                                |
| `sessionResumptionTimeoutSeconds` | integer      | `60`; valid range 1–86,400                                                                                            |
| `limits.maxConnections`           | integer      | `128`; valid range 1–65,536                                                                                           |
| `limits.maxClientSessions`        | integer      | `128` per authenticated username; valid range 1–10,000                                                                |
| `limits.maxTotalPlayers`          | integer      | `256` server-wide; valid range 1–10,000                                                                               |
| `limits.maxPlayersPerClient`      | integer      | `16`; valid range 1–1,000 and no greater than `maxTotalPlayers`                                                       |
| `limits.maxMessageBytes`          | integer      | `65,536`; valid range 1,024–1,048,576                                                                                 |
| `limits.requestTimeoutMs`         | integer      | `30,000`; valid range 1–300,000; also bounds the WebSocket handshake                                                  |
| `limits.maxInFlightRequests`      | integer      | `16` per WebSocket; valid range 1–4,096                                                                               |
| `limits.maxRequestsPerSecond`     | integer      | `60` per WebSocket; valid range 1–100,000                                                                             |
| `limits.eventBuffer`              | integer      | `128` events per client session; valid range 1–65,536                                                                 |
| `media.allowedFileRoots`          | string array | Empty by default, which denies file playback; relative paths use the config directory, `~` expands to the user's home |
| `media.allowedUrlHosts`           | string array | Empty by default, which denies URL playback; exact host and subdomains are matched, or explicitly use `*`             |
| `media.allowHttp`                 | boolean      | `true`; controls `http:` URLs                                                                                         |
| `media.allowHttps`                | boolean      | `true`; controls `https:` URLs                                                                                        |
| `media.blockPrivateNetworks`      | boolean      | `true`; rejects hostnames resolving to private or special IP ranges                                                   |
| `audio.opus.bitrate`              | integer      | `128000` bits per second; valid range 500–512000                                                                      |
| `audio.opus.complexity`           | integer      | `9`; valid range 0–10                                                                                                 |
| `audio.opus.vbr`                  | boolean      | `true`; enables variable bitrate                                                                                      |
| `observability.console`           | boolean      | `true`; enables the existing console subscriber for this server process                                               |

For an empty `limits`, `media`, `observability`, or `bind` object, the defaults above apply. The
`users` array is required. Discord bot identity is not server configuration: each remote client
sends its bot snowflake in the `X-Remedia-Bot-Id` WebSocket handshake header.

## Opus encoder settings

```json
{
  "audio": {
    "opus": {
      "bitrate": 128000,
      "complexity": 9,
      "vbr": true
    }
  }
}
```

This optional section can be added to an existing configuration. Omitting `audio`, `opus`, or any
individual property uses the defaults shown above. Values are validated before startup; unknown
fields are rejected, including inside `audio` and `opus`.

`bitrate` is in **bits per second, not kilobits**: `128000` means 128 kbit/s for the stereo stream.
Higher bitrates generally preserve more detail at the cost of bandwidth. `complexity` trades CPU
for encoding quality: 0 uses the least computation, 10 the most; 9 is the music-oriented default.
With `vbr: true`, libopus varies packet sizes according to the audio while targeting the configured
bitrate. `false` requests constant bitrate. Encoding stays at 48 kHz stereo with 20 ms frames and
libopus's `Application::Audio` mode.

All server players receive these settings, with an independent, lazily created encoder for each
output. Settings apply only when encoding PCM. Compatible Opus passthrough forwards the original
packets without constructing an encoder, so these settings cannot change their bitrate or quality.
There are no client or guild overrides, and the RPC protocol is unchanged. Embedded Node.js uses
the same core defaults without loading this JSON file; it has no JavaScript encoder-setting API.
See [Opus encoding output](/docs/core/playback#opus-encoding-output) for the Rust configuration API.

## Environment references

String fields that may contain secrets or deployment-specific paths can use only this exact
reference syntax:

```json
{
  "password": "env('REMEDIA_RPC_PASSWORD')"
}
```

Supported fields are `bind.host`, each user `username` and `password`, each
`media.allowedFileRoots` entry, and each `media.allowedUrlHosts` entry. The variable name must match
`[A-Za-z_][A-Za-z0-9_]*`. A missing variable fails startup. The resolved value is treated as literal
text; no interpolation or expression evaluation occurs. Numeric and boolean fields do not accept
environment references.

## Media access restrictions

File paths are canonicalized before use and must be regular files beneath one of the configured
roots. Use narrowly scoped roots containing only media the server should serve.

Remote inputs accept only HTTP(S), according to `allowHttp` and `allowHttps`. `allowedUrlHosts` is an
explicit host allowlist; an empty list denies all hosts. A listed parent domain also matches its
subdomains. `"*"` opts in to any public hostname. Private, loopback, link-local, multicast, reserved,
and documentation IP ranges are rejected by default after DNS resolution.

FFmpeg follows HTTP redirects, and the core HTTP input owns the redirected request. The server
cannot revalidate each redirect target in this v0 implementation. For untrusted URL inputs, use a
strict host allowlist and enforce outbound egress rules that block internal networks and cloud
metadata endpoints. Do not disable `blockPrivateNetworks` or configure `*` unless the media URLs are
trusted and network egress is independently restricted.

Raw FFmpeg filtergraphs are trusted application configuration because filters can access external
resources. Do not expose unrestricted filter changes to untrusted clients.

## Observability

The server initializes the existing `remedia-observability` context. It does not add a second
logging configuration. `REMEDIA_LOG` takes precedence over `REMEDIA_DEBUG=1`; `REMEDIA_LOG_FORMAT`
accepts `text` or `json`; `REMEDIA_OTEL_ENABLED=true` enables optional OTLP traces and metrics. The
standard `OTEL_*` endpoint, protocol, resource, and sampling variables are honored by the shared
crate. `observability.console: false` disables server console output while preserving configured
diagnostic receivers and OTLP exporters. See [Observability](/docs/observability/configuration).

The process never logs passwords, authorization headers, Discord voice tokens, session keys, MLS
material, or full media URLs. Treat RPC credentials, resume credentials, and voice credentials as
secrets even when they are not written to logs.
