title: Install the server

Install the self-contained server and its license files:

```sh
curl -fsSL https://remedia.twlite.dev/install.sh | sh
```

```powershell
irm https://remedia.twlite.dev/install.ps1 | iex
```

The installer downloads a GitHub release archive, verifies its SHA-256 digest,
and installs the CLI/runtime executable pair. No FFmpeg installation or library
path configuration is needed. `--no-ffmpeg` and `-NoFFmpeg` remain accepted no-ops.
Set `REMEDIA_INSTALL_DIR` to choose the prefix and `REMEDIA_VERSION` to pin a release.
Windows also accepts `-InstallDir`, `-Version`, and `-ArchivePath` for a locally
downloaded archive; its checksum is still verified against release metadata.

The installer creates `remedia` and `remedia-server` commands, updates PATH, and
copies LICENSE, LICENSES.md, COPYING.GPLv3 and third-party acknowledgments into
`licenses` alongside the installed executables. Native binaries are subject to
GPLv3-or-later obligations. [Bundled FFmpeg](/docs/node/ffmpeg-9) explains the source
archive and distribution model.

For automated or isolated installations, pass `--no-modify-path` (POSIX) or
`-NoModifyPath` (PowerShell), or set `REMEDIA_NO_MODIFY_PATH=1` in the installer
process environment. This also works with `remedia update` when the installed CLI
contains the updated installer. Shell startup files and the Windows user PATH
remain unchanged; invoke the wrappers directly from the installation prefix’s
`bin` directory or configure PATH yourself.

## Version directories and updates

A fresh installation uses `~/.remedia/libexec/vVERSION/` (or the chosen prefix),
containing both `remedia-server` and `remedia-server-runtime` (`.exe` on Windows).
The `bin` wrappers read `libexec/current.txt` once; the CLI launches the runtime
beside its own executable. Both therefore resolve to one installed version.
No executable path contains a staging or temporary suffix.

The installer locks the prefix, downloads and verifies the archive, stages the
complete pair and notices on the same filesystem, then renames that directory into
place. It atomically updates `current.txt` only after staging succeeds. Repeating
an installation verifies the cached pair's hashes and reuses it; it never overwrites
those executables. A failed download, checksum, staging or activation keeps the
previous pair active. Interrupted staging is cleaned by the next successful run;
a complete inactive version can be reused without downloading again.

One previous version is retained in `libexec/previous.txt`. To select a published
version again, use the existing `REMEDIA_VERSION` option (or Windows `-Version`);
there is no separate version manager. Configuration files are left in place.

Legacy `vVERSION-tmp.*` Unix directories and Windows GUID directories migrate on
the next installer run using this implementation. Future commands use the stable
path while running processes continue using their original files. The old directory
is retained for at least one invocation and while any process uses it; later installs
clean idle obsolete directories. Unix uses optional `lsof` for conservative process
inspection; Windows uses process executable paths. If inspection is unavailable or
permission is denied, old files are retained. No playback process is stopped for
migration. Finish those processes normally before expecting their files to be removed.
A damaged or different fixed version is never replaced while active or possibly in use.

Published v0.3.0 CLIs contain their old installer. Their first upgrade can still
create a legacy directory; the updated CLI's next normal `remedia update` migrates
it automatically, without a manual reinstall or server restart. Server archives
keep the old entry allowlist so those embedded updaters can still install them.
The new installers serialize concurrent runs with Windows file locking, Linux
`flock` (util-linux/BusyBox), or macOS's built-in `lockf`.

## Platform selection

The installer selects Linux x64/ARM64 GNU or musl by CPU and libc, macOS x64/ARM64,
or Windows x64/ARM64 by native OS architecture (including an emulated shell).
Windows ARM64 runs the native server and addon test matrix. Linux musl x64 and
ARM64 run server startup and addon decoding checks in clean Alpine containers;
these smoke checks provide narrower coverage than the GNU Linux test matrix.
Windows ARM64 requires Windows 11, matching the existing installer OS boundary.
Windows x86, Linux ARMv7 and FreeBSD servers remain outside the release target
list even when their compilation probes succeed.

## Configure and verify

```sh
remedia --generate-config-file ./remedia.config.json
remedia --version
remedia doctor --config ./remedia.config.json
remedia serve --config ./remedia.config.json
```

Doctor reports the bundled FFmpeg version, license, configure flags and library
ABI capabilities, then validates environment files, configuration and plugin hosts.
See the [CLI reference](/docs/server/cli) for configuration and environment flags.

## Update or upgrade

```sh
remedia update
remedia upgrade
```

Both commands run the installer embedded in the current executable. They resolve
the latest stable release, falling back to a prerelease when none exists. Identical
full versions are skipped. Downloads and checksum failures leave the active binary
pair in place. Versions are staged separately before an atomic pointer switch;
a running instance continues until restarted. Restart after updating; playback
sessions do not survive a restart. Windows prefers PowerShell 7 and falls back to
Windows PowerShell 5.1. Existing configuration files are preserved.

The installer needs GitHub access, tar, and curl (POSIX) or PowerShell (Windows).
Inspect scripts before execution and pin trusted revisions for production.
GitHub asset digests do not protect against a compromised release account.

## Corresponding source instructions

`licenses/LICENSES.md` contains version-specific source retrieval directions.
The matching GitHub release provides `SOURCE_DISTRIBUTION.md` and
`source-manifest.json` for releases after v0.3.0. They identify the exact source,
shared dependency snapshot, hashes and rebuild steps. Server archives retain the
entry layout accepted by older embedded updaters; v0.3.0's assets are unchanged.
See [licensing](/docs/licensing).
