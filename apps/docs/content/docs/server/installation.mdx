title: Install the server
description: One-command installation, FFmpeg 9 runtime provisioning, upgrades, and platform support.
---

Install the self-contained server and its license files:

```sh
curl -fsSL https://remedia.twlite.dev/install.sh | sh
```

```powershell
irm https://remedia.twlite.dev/install.ps1 | iex
```

The installer downloads a GitHub release archive, verifies its SHA-256 digest,
and installs the CLI/runtime executable pair. No FFmpeg installation or library
path configuration is needed. `--no-ffmpeg` and `-NoFFmpeg` remain accepted no-ops.
Set `REMEDIA_INSTALL_DIR` to choose the prefix and `REMEDIA_VERSION` to pin a release.
Windows also accepts `-InstallDir`, `-Version`, and `-ArchivePath` for a locally
downloaded archive; its checksum is still verified against release metadata.

The installer creates `remedia` and `remedia-server` commands, updates PATH, and
copies LICENSE, LICENSES.md, COPYING.GPLv3 and third-party acknowledgments into
`licenses` alongside the installed executables. Native binaries are subject to
GPLv3-or-later obligations. [Bundled FFmpeg](/docs/node/ffmpeg-9) explains the source
archive and distribution model.

## Platform selection

The installer selects Linux x64/ARM64 GNU or musl by CPU and libc, macOS x64/ARM64,
or Windows x64/ARM64 by native OS architecture (including an emulated shell).
The release pipeline requires target tests before publishing. The newly added
Windows ARM64 and musl candidates still need their first platform CI validation;
build configuration alone does not establish support. Windows ARM64 requires
Windows 11, matching the existing installer OS boundary.

## Configure and verify

```sh
remedia --generate-config-file ./remedia.config.json
remedia --version
remedia doctor --config ./remedia.config.json
remedia serve --config ./remedia.config.json
```

Doctor reports the bundled FFmpeg version, license, configure flags and library
ABI capabilities, then validates environment files, configuration and plugin hosts.
See the [CLI reference](/docs/server/cli) for configuration and environment flags.

## Update or upgrade

```sh
remedia update
remedia upgrade
```

Both commands run the installer embedded in the current executable. They resolve
the latest stable release, falling back to a prerelease when none exists. Identical
full versions are skipped. Downloads and checksum failures leave the active binary
pair in place. Versions are staged separately before an atomic pointer switch;
a running instance continues until restarted. Restart after updating; playback
sessions do not survive a restart. Windows prefers PowerShell 7 and falls back to
Windows PowerShell 5.1. Existing configuration files are preserved.

The installer needs GitHub access, tar, and curl (POSIX) or PowerShell (Windows).
Inspect scripts before execution and pin trusted revisions for production.
GitHub asset digests do not protect against a compromised release account.
