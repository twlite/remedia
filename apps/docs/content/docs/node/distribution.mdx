The @remedia/node package contains the JavaScript loader, compiled TypeScript declarations, and
optional N-API platform packages generated by @napi-rs/cli. Npm installs the platform package that
matches the current operating system and CPU. The loader does not download binaries during
installation or when imported.

Each platform package `@remedia/node-<platform>` contains one `node.<platform>.node`
engine addon, license notices, and version-specific source-distribution instructions.
FFmpeg is statically linked. There is no bootstrap addon or external FFmpeg discovery.
`native.js` and `native.d.ts` remain generated by NAPI-RS from Rust.

## Release-tested platforms

The beta release pipeline includes these native packages after each target passes its native build, Rust tests,
binary inspection, and Node.js integration tests:

| Runtime target          | N-API package                  |
| ----------------------- | ------------------------------ |
| Linux x64 with glibc    | @remedia/node-linux-x64-gnu    |
| Linux ARM64 with glibc  | @remedia/node-linux-arm64-gnu  |
| macOS x64               | @remedia/node-darwin-x64       |
| macOS ARM64             | @remedia/node-darwin-arm64     |
| Windows x64 with MSVC   | @remedia/node-win32-x64-msvc   |
| Windows ARM64 with MSVC | @remedia/node-win32-arm64-msvc |

Release jobs test Node.js 22.18, 24, and 26. Pull requests use Node 24 for native
integration. Fresh-process and packed-package tests run without FFmpeg, managed
library directories, or loader environment variables. No media library is downloaded
at installation or import time.

Additional npm platform packages are included by the current release packer:

| Target                     | Verification configured in CI                                       |
| -------------------------- | ------------------------------------------------------------------- |
| Linux x64 and ARM64 musl   | Native-architecture container startup and addon decoding configured |
| Linux ARMv7 hard-float GNU | Cross-build and linking checks; native runtime unverified           |
| Windows x86 MSVC           | Cross-build only; runtime compatibility remains unverified          |
| Android ARM64 and ARMv7    | NDK 27.2 / API 24 cross-build. No native runtime integration tests  |
| FreeBSD x64                | FreeBSD 15.1 VM build and native runtime integration tests          |

The package gate requires all 13 engine addons. Eight server targets are retained:
Linux GNU and musl x64/ARM64, macOS x64/ARM64, Windows x64/ARM64. Android,
Windows x86 and ARMv7 addons remain experimental until native runtime validation.
FreeBSD x64 has native VM tests but no released server. Unpublished server probes
are omitted from ordinary CI; they do not establish a supported server target.

## Bundled FFmpeg

Official native packages statically link FFmpeg 9 with GPL and version3 enabled.
No external media library installation is needed. Native npm packages use
`SEE LICENSE IN LICENSES.md`; the combined binaries are subject to GPLv3-or-later
obligations. FFmpeg-independent packages and Remedia's original source remain MIT.
[Bundled FFmpeg](/docs/node/ffmpeg-9) documents diagnostics and corresponding source.

### Package selection

The generated platform packages include os and cpu restrictions. Linux GNU and musl packages
also declare their matching libc value. These fields let npm select an appropriate package and
prevent a GNU addon from being installed as a musl addon.

## Client package

@remedia/client is pure TypeScript. It declares @remedia/node as an optional peer dependency for
embedded playback, so applications that use only remote server nodes can install the client without
the native package. During release packing, pnpm resolves this workspace peer dependency to the
actual released @remedia/node version.

## Plugin host package

`@remedia/plugin-host` is pure TypeScript and ships with each npm release using the same
version and dist-tag as `@remedia/node` and `@remedia/client`. Release packaging builds it,
verifies both the main entrypoint and the `@remedia/plugin-host/node` HTTP middleware
entrypoint (JavaScript and declarations), and includes the shared license notices.
It requires Node.js 22.18 or newer, loads through `import` or `require()`, and does not require
FFmpeg or the native addon.

```sh
npm install @remedia/plugin-host
```

See the [plugin host guide](/docs/server/plugins) for direct dispatch and HTTP hosting examples.

## Install the packages

```sh
npm install @remedia/node
# Remote-only consumers need only this package:
npm install @remedia/client
```

Both packages require Node.js 22.18.0 or newer. See [bindings](/docs/node/bindings) and
[client configuration](/docs/client/overview) for API examples.

## ESM and CommonJS

`@remedia/node`, `@remedia/client`, `@remedia/plugin-host` and `@remedia/config` each ship one ES
module build with no top-level await. Their export maps use the `default` condition, so both
import styles load the same files:

```js
// ES modules
import { RemediaClient } from '@remedia/client';
import { Remedia, getFFmpegRuntime } from '@remedia/node';
import { createPluginHost } from '@remedia/plugin-host';
import { createNodeMiddleware } from '@remedia/plugin-host/node';
import { RemediaConfigSchema } from '@remedia/config';
import schema from '@remedia/config/schema.json' with { type: 'json' };
```

```js
// CommonJS
const { RemediaClient } = require('@remedia/client');
const { Remedia, getFFmpegRuntime } = require('@remedia/node');
const { createPluginHost } = require('@remedia/plugin-host');
const { createNodeMiddleware } = require('@remedia/plugin-host/node');
const { RemediaConfigSchema } = require('@remedia/config');
const schema = require('@remedia/config/schema.json');
```

CommonJS loading relies on Node.js `require()` of synchronous ES modules, which every supported
Node.js version (22.18 and newer) enables without a flag or warning. Because there is a single build,
`require()` and `import()` return the same module instance in one process: classes keep their
identity across both styles and the native addon loads once.

Loading is synchronous; startup is not. Importing `@remedia/node` loads the platform addon but
starts no engine, thread or socket. `Remedia.create()` and `RemediaClient.create()` stay
asynchronous and are where resources begin. `@remedia/client` loads `@remedia/node` only when an
embedded node starts, so remote-only CommonJS and ESM applications never resolve the native package.

Limitations:

- Node.js versions before 22.12 cannot `require()` these packages. They are below the supported
  minimum.
- CommonJS has no top-level await, so call `Remedia.create()` and `RemediaClient.create()` inside an
  async function.
- TypeScript CommonJS projects need `"module": "NodeNext"` (or `"Node20"`) with TypeScript 5.8 or
  newer. `"Node16"` reports TS1479 because it models a Node.js version without `require()` of ES
  modules.

Release packing installs the packed tarballs into clean projects and checks both import styles,
mixed `require()` and `import()`, subpath exports, embedded and remote-only clients, and a missing
platform package on every tested Node.js version.

## Runtime diagnostics and distribution

`getFFmpegRuntime()` reports the bundled FFmpeg build. Runtime environment variables
cannot select a different FFmpeg. See [diagnostics](/docs/node/ffmpeg-9) for the
version, configuration, license and library ABI fields.

Native addon packages and server archives include LICENSES.md and COPYING.GPLv3
alongside MIT and third-party notices. Combined native binaries are distributed
under GPLv3-or-later obligations. `SOURCE_DISTRIBUTION.md` and `source-manifest.json` in native npm packages and
the GitHub release identify complete source for that exact version. Server archives
include retrieval directions in `LICENSES.md`. Actual sources are made public in this repository's source-only
releases before npm publication. Unchanged dependency snapshots are reused;
release-specific source and target records remain small. v0.3.0 retains its original
source archive without modification.
See [licensing](/docs/licensing).
