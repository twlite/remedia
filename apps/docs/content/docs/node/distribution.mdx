# Package distribution

The @remedia/node package contains the JavaScript loader, compiled TypeScript declarations, and
optional N-API platform packages generated by @napi-rs/cli. npm installs the platform package that
matches the current operating system and CPU. The loader does not download binaries during
installation.

## Release-tested platforms

Stable releases include these native packages after each target passes its native build, Rust tests,
binary inspection, and Node.js integration tests:

| Runtime target         | N-API package                 |
| ---------------------- | ----------------------------- |
| Linux x64 with glibc   | @remedia/node-linux-x64-gnu   |
| Linux ARM64 with glibc | @remedia/node-linux-arm64-gnu |
| macOS x64              | @remedia/node-darwin-x64      |
| macOS ARM64            | @remedia/node-darwin-arm64    |
| Windows x64 with MSVC  | @remedia/node-win32-x64-msvc  |

These release jobs run with Node.js 22.18, 24, and 26. The package declares Node.js 22.18 or newer.
The Node-API addon also has runtime tests for decoding and playback, addon loading, Discord voice
components, the embedded client, and the standalone server using the built server binary.

The following targets are experimental and are not included in published platform packages:

| Target                   | Current dependency or verification gap                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Linux x64 and ARM64 musl | cargo-zigbuild supplies a cross-linker, but the workflow has no target-built FFmpeg 7 sysroot                 |
| Linux ARMv7 GNU          | The FFmpeg 7 recipe has no ARMv7 libraries, headers, or cross pkg-config metadata                             |
| Windows x86 MSVC         | The configured FFmpeg 7 libraries are x64 only                                                                |
| Windows ARM64 MSVC       | Matching FFmpeg 7 ARM64 import libraries and DLLs are not configured                                          |
| Android ARM64 and ARMv7  | The workflow configures NDK 27.2 linkers for API 24, but has no FFmpeg 7 builds for those ABIs                |
| FreeBSD x64              | A FreeBSD 15 VM attempts native build and runtime tests after installing FFmpeg 7; it is not a release target |

The experimental jobs do not stop required target tests and their artifacts are not published. WASI
is excluded. A target becomes part of an npm release only after its FFmpeg 7 dependencies, runtime
tests, and package metadata have been verified.

## FFmpeg runtime libraries

Remedia links dynamically to FFmpeg 7. Install compatible FFmpeg 7 shared libraries on the runtime
machine before loading @remedia/node. npm installs the Remedia addon but does not install FFmpeg.
The addon expects these FFmpeg library ABI majors:

- libavcodec 61
- libavformat 61
- libavutil 59
- libavfilter 10
- libswresample 5

Linux GNU and macOS releases are linked against the matching shared FFmpeg libraries. Windows
requires the matching FFmpeg 7 DLLs and a compatible Microsoft Visual C++ v14 runtime. The Opus
encoder is built from bundled source and statically linked; a separate system Opus library is not
required. See the [Node.js bindings guide](/docs/node/bindings) for local build prerequisites.

The generated platform packages include os and cpu restrictions. Linux GNU and musl packages
also declare their matching libc value. These fields let npm select an appropriate package and
prevent a GNU addon from being installed as a musl addon.

## Client package

@remedia/client is pure TypeScript. It declares @remedia/node as an optional peer dependency for
embedded playback, so applications that use only remote server nodes can install the client without
the native package. During release packing, pnpm resolves this workspace peer dependency to the
actual released @remedia/node version.
