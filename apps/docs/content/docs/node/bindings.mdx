# Node.js bindings

`@remedia/node` is a Rust N-API addon with a thin TypeScript wrapper. It calls
`remedia-core`, `remedia-discord`, and `remedia-observability` in the current
Node process. It does not start `remedia-server` and does not install a global
Rust tracing subscriber.

The package is under development and is currently private. It supports local
files, HTTP(S) URLs, in-memory `Buffer`/`Uint8Array` data, and Node.js binary
`Readable` streams. A standalone playback session decodes into a null output
for inspection and testing; a Discord session connects the existing Opus
output to the voice transport. A local audio device, server RPC, full Discord
Gateway connection, and REST client are not implemented by these bindings; the
Node package adapts a Gateway client supplied by the application.

For applications that select between direct embedded playback and one or more
`remedia-server` nodes, use the separate pure TypeScript
[`@remedia/client` guide](/docs/client/overview). The high-level client loads
this native package lazily and only when an embedded node is configured; remote
only consumers do not need native FFmpeg or N-API dependencies.

## Build prerequisites

Use the repository's pinned Rust toolchain, Node.js 22.18 or newer, and pnpm
12.16.1. Building the native addon requires the FFmpeg development libraries
used by `remedia-core`. The Opus encoder is built from bundled source and linked
statically, so a separate system libopus development package is not required.
From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm --filter @remedia/node test
pnpm --filter @remedia/node build
```

The test command builds a debug addon and runs local Node integration tests.
`build` creates the release addon and TypeScript declarations. The N-API loader
and native declarations are generated from Rust source by `@napi-rs/cli`.

## Create and close an instance

Create each independent engine context with `await Remedia.create()`. The
instance owns its playback sessions, voice connections, bounded diagnostics
queue, and optional OpenTelemetry providers. Call `close()` during normal
shutdown; it stops playback, disconnects voice transports, flushes telemetry,
and releases native workers. It can be called more than once.

```ts
import { Remedia } from '@remedia/node';

const remedia = await Remedia.create();
const playback = remedia.createPlaybackSession();

try {
  const media = await playback.play({ file: './audio/example.wav' });
  console.log(media.codec, media.durationMs);

  const finalState = await playback.wait();
  console.log(finalState, playback.position);
} finally {
  await playback.dispose();
  await remedia.close();
}
```

`MediaSource` is an explicit union: `{ file: string }`, `{ url: string }`,
`{ buffer: Buffer | Uint8Array }`, or `{ stream: Readable }`. The binding does
not infer a source type from arbitrary strings. The returned
`AudioStreamInfo` contains the selected stream index, codec, original sample
rate and channel layout when known, duration when known, bit rate, and media
metadata.

Standalone sessions currently use `NullOutput`, which consumes decoded PCM as
fast as possible and does not produce sound. Discord sessions use the
transport-independent core Opus adapter and send the resulting packets through
their associated voice connection.

## Buffer and Readable inputs

Pass encoded media bytes directly with a `Buffer` or `Uint8Array`:

```ts
import { readFile } from 'node:fs/promises';
import { Remedia } from '@remedia/node';

const bytes = await readFile('./audio/track.mp3');
const remedia = await Remedia.create();
const playback = remedia.createPlaybackSession();
try {
  await playback.play({ buffer: bytes });
  console.log(await playback.wait());
} finally {
  await playback.dispose();
  await remedia.close();
}
```

For generated or streamed data, pass a Node.js `Readable` that yields only
`Buffer` or `Uint8Array` chunks. Object-mode streams and other chunk values fail
the playback operation with a source error. The pump starts before decoder
initialization, so FFmpeg can probe while the producer is writing:

```ts
import { Readable } from 'node:stream';
import { Buffer } from 'node:buffer';
import { Remedia } from '@remedia/node';

function makeWave(): Buffer {
  const sampleRate = 48_000;
  const sampleFrames = 4_800;
  const bytes = Buffer.alloc(44 + sampleFrames * 2);
  bytes.write('RIFF', 0);
  bytes.writeUInt32LE(bytes.length - 8, 4);
  bytes.write('WAVEfmt ', 8);
  bytes.writeUInt32LE(16, 16);
  bytes.writeUInt16LE(1, 20); // PCM
  bytes.writeUInt16LE(1, 22); // mono
  bytes.writeUInt32LE(sampleRate, 24);
  bytes.writeUInt32LE(sampleRate * 2, 28);
  bytes.writeUInt16LE(2, 32);
  bytes.writeUInt16LE(16, 34);
  bytes.write('data', 36);
  bytes.writeUInt32LE(sampleFrames * 2, 40);
  return bytes;
}

const bytes = makeWave();
const source = Readable.from(
  [bytes.subarray(0, 16), bytes.subarray(16, 2_000), bytes.subarray(2_000)],
  { objectMode: false },
);
const remedia = await Remedia.create();
const playback = remedia.createPlaybackSession();
try {
  await playback.play({ stream: source });
  console.log(await playback.wait());
} finally {
  await playback.dispose();
  await remedia.close();
}
```

The native queue is capped at 512 KiB of pending bytes per stream. Writes wait
for decoder consumption before the Readable pump asks for more data. When
playback is paused, the queue fills and backpressure propagates to the source;
this prevents unbounded buffering. The input is incremental and does not first
materialize the complete stream. A single producer chunk and the Readable's own
high-water mark add to the queue's memory use.

Remedia copies Buffer/Uint8Array data into native-owned memory. For a Readable,
the feeder copies each chunk before submitting it to native code. Remedia owns
the feeder and detaches it on stop, dispose, or `Remedia.close()`, but it does
not destroy the caller-owned Readable. The source is paused and no further
chunks are consumed after cancellation. A producer error is propagated through
decoder state and `playback.error` or the rejected `play()` Promise, not through
diagnostic events.

In-memory buffers support byte-offset seeking when FFmpeg can seek the
container. A producer-backed Readable is non-seekable; seeking it returns an
unsupported-seeking error. File and HTTP behavior is unchanged, and supported
containers/codecs depend on the installed native FFmpeg libraries.

## Playback controls

`PlaybackSession.state` reports `idle`, `starting`, `playing`, `pausing`,
`resuming`, `paused`, `stopping`, `stopped`, `completed`, or `failed`.
`play()` resolves only after the native decoder has opened and selected an
audio stream. It rejects on initialization failure. Starting a second source
while one is active is rejected; stop the current source first.

The session methods are Promise-based where they wait on native work:

```ts
await playback.pause();
await playback.resume();
await playback.seek(12_500); // milliseconds
await playback.stop();
const outcome = await playback.wait();
```

Pausing and seeking take effect at a decoder/output boundary. `stop()` cancels
playback but does not disconnect an associated Discord voice transport. A
normal EOF moves to `completed`; an unrecoverable decoder or output error moves
to `failed` and is available as `playback.error`. API failures reject their
Promise and remain separate from debug diagnostics.

`position` returns `mediaMs`, `mediaPositionAccuracy`, `submittedMs`, and
`playedMs`. `mediaMs` is the original source timeline associated with the latest
filtered PCM accepted by the output. Its accuracy is `timestamp` when based on
valid source timestamps, `estimated` when decoding or a filtergraph makes that
mapping uncertain, and `null` before a position is available. It is not proof
that the listener has heard those samples. `submittedMs` is the filtered PCM
output timeline (also used for Opus continuity), and `playedMs` is populated
only when the output reports actual consumption. A Discord transport currently
cannot report audible playback time, so `playedMs` is `null`; the Discord test
bot displays source progress with an approximation marker in that case. The
null output consumes the whole stream without real-time pacing, so positions
can advance to the end quickly. `durationMs` is `null` when the source does not
provide a duration.

## Lifecycle events and pre-play hooks

`PlaybackSession`, `DiscordSession`, and their owning `Remedia` instance use
Node's built-in typed `EventEmitter`. Stable event names are exported as
constants, with matching string-union types:

```ts
import { PlaybackSessionEvents } from '@remedia/node';

const playback = remedia.createPlaybackSession<{ trackId: string }>();
playback.on(PlaybackSessionEvents.playbackCompleted, (event) => {
  // event.customMetadata is { trackId: string } | undefined
  console.log(event.generation, event.customMetadata);
});
```

`PlaybackSessionEvents` contains `playbackStarted`, `playbackCompleted`,
`playbackStopped`, `playbackFailed`, `playbackPaused`, `playbackResumed`,
`playbackSeeked`, `filterChanged`, `volumeChanged`, and `sessionDisposed`.
`VoiceSessionEvents` contains `voiceStateChanged` and `voiceFailed`. `Remedia`
forwards lifecycle events from its sessions and also emits `debug` diagnostics.
The constants can be used with `on`, `once`, and `off`; the event map infers
each payload. The same-named exported type `PlaybackSessionEvents` is the union
of event-name string literals. Operational failures use `playbackFailed` or `voiceFailed`, not
Node's special `error` event.

Events describe engine transitions, not Discord audibility. `playbackStarted`
fires after the native media pipeline has started; it does not mean a listener
has heard a sample. `playbackCompleted` means decoding and processing reached
natural EOF; it does not guarantee a transport or speaker buffer has drained.
`playbackStopped` is distinct from natural completion. Pause, resume, seek,
filter, and volume events are emitted only after a successful change; repeated
idempotent operations do not emit duplicates. A rejected operation does not
emit its successful state-change event. Session disposal emits
`sessionDisposed` once.

Every playback event includes a wrapper `sessionId`, native source `generation`,
and `nodeId` (`null` for direct `@remedia/node` sessions). Discord-session
payloads also include `guildId`. A generation identifies one source start, so
terminal events cannot be confused with a later source. Event listeners run
outside native locks. Synchronous listener exceptions are isolated and reported
as a Node process warning (`REMEDIA_LISTENER_ERROR`); they do not fail playback.

Attach arbitrary application metadata to one source without serializing it:

```ts
interface MyMetadata {
  requestedBy: string;
  trackId: string;
}

const voice = remedia.createDiscordSession<MyMetadata>({ guildId, channelId, userId });
await voice.play(
  { url },
  {
    customMetadata: { requestedBy: interaction.user.id, trackId: 'track-123' },
  },
);
```

The same object reference is included in lifecycle events for that generation,
including delayed terminal events. It remains in JavaScript memory only and is
released when that source reaches a terminal state or the session is disposed.
Remedia does not interpret it as track or queue data.

`hooks.beforePlay()` registers awaited local middleware. Hooks run in
registration order before native playback starts; returning
`{ cancel: true, reason }` cancels the operation, and a thrown/rejected hook
rejects `play()` without starting media. The context contains the source,
metadata, and an `AbortSignal`. Aborting while hooks are running cancels the
pending start; aborting after startup requests stop for that playback. Hooks
are application middleware, not server authorization, and are cleared when the
session is disposed. Unlike ordinary event listeners, hooks may delay or cancel
playback deliberately.

## Native filters and master volume

Both `PlaybackSession` and `DiscordSession` expose the core's raw FFmpeg audio
filtergraph and an independent master gain. No named music presets are part of
`@remedia/node`.

```ts
await voice.filters.set('bass=gain=8,volume=0.8');
await voice.setVolume(0.75);

await voice.filters.set('tremolo=f=5:d=0.6'); // replaces the previous graph live
await voice.filters.clear();
console.log(voice.filters.graph, voice.volume); // null, 0.75
```

Filter graphs can be set before playback or before `DiscordSession.connect()`.
On an active track, a change is validated first and takes effect at the next
decoded PCM boundary. Remedia discards delayed samples still held in the
previous stateful graph, keeps PCM already accepted by the output, and retains
the current decoder and Discord connection. It does not perform a seek flush,
reset the Opus encoder, or invalidate queued RTP packets. A partial Opus frame
is retained and can contain accepted PCM from both sides of the graph boundary;
sample positions remain contiguous. Invalid graphs reject without replacing
the graph already in use.
If EOF wins a race before another PCM boundary exists, the update is retained
for the next source on that session. A seek that loses an EOF race rejects with
an invalid-state error.
Pass a raw audio graph expression, not an FFmpeg command-line option; empty or
whitespace-only strings reject, and `clear()` disables filtering. The parser
requires one effective PCM input and output but does not sandbox filters that
may access files or URLs. Only pass trusted graph strings to the engine.

`volume` is a normalized linear gain from `0` through `2`; the default is `1`.
`setVolume(0)` mutes without stopping playback, `setVolume(1)` is unity, and
values above one may clip. Samples are clamped to `[-1, 1]`; this is not
limiting or loudness normalization. Volume is applied after the graph and is
preserved when filters change or tracks are replaced on the same session.
Each session has independent settings, and disposal releases them.

Time-changing filters alter the filtered PCM timeline. `position.mediaMs` tracks
the original source position associated with the latest output boundary and is
marked estimated whenever timestamps or a graph's buffering/timing prevent an
exact mapping. Remedia does not parse filter expressions to guess a constant
speed ratio. `position.submittedMs` advances by filtered samples submitted to
the output, not source media time. `seek()` remains relative to the original
source timeline and resets both timelines to the requested position. Discord
does not report audible position, so `playedMs` remains `null`; source progress
shown by the Discord test bot is therefore approximate. Graph replacement,
seek, pause, stop, and end-of-stream draining are handled by the native playback
worker; no graph or PCM work runs on Node's event loop.

## Discord Gateway adapter

The application still owns its Discord Gateway client and decides when to
join a channel. Remedia now adapts that client: supply a function that sends a
Gateway payload for a guild, then forward raw Gateway packets to
`remedia.receive()`. Remedia sends OP 4, collects the matching
`VOICE_STATE_UPDATE` and `VOICE_SERVER_UPDATE` in either order, and calls the
native transport only after both are valid. `connect()` resolves after the
voice WebSocket, UDP transport, encryption, and required DAVE setup are ready.

```ts
import { Remedia } from '@remedia/node';

const remedia = await Remedia.create({
  send(guildId, payload) {
    return sendToShard(guildId, payload);
  },
});

discord.on('raw', (packet) => remedia.receive(packet));

const voice = remedia.createDiscordSession({
  guildId: '123456789012345678',
  channelId: '234567890123456789',
  userId: '345678901234567890',
});

try {
  await voice.connect();
  await voice.play({ url: 'https://example.org/audio.mp3' });
  console.log(voice.connectionState, await voice.wait());
  await voice.stop(); // leaves the voice connection open
} finally {
  await voice.disconnect();
  await remedia.close();
}
```

Snowflakes remain decimal strings in JavaScript and are validated before any
Gateway request. `connect()` defaults to a 45-second timeout and accepts
`{ timeoutMs, signal }` for per-attempt timeout and `AbortSignal` cancellation.
An interrupted connection sends OP 4 with `channel_id: null` and discards the
pending credentials. `disconnect()` also sends this leave request, stops active
playback, closes the native transport, and leaves the wrapper reusable for a
later `connect()` with fresh Gateway events. `dispose()` disconnects and removes
the session from its `Remedia` instance. Only one live wrapper per guild is
allowed in an instance. Gateway responses are not persisted or logged; the
server token and endpoint are discarded after native setup, and pending data is
reset before each new exchange and on disconnect.

An abort or timeout rejects the pending `connect()` and requests a Gateway
leave. If native voice setup has already started, its network handshake cannot
be interrupted mid-operation; `disconnect()` waits for the transport's bounded
timeouts and disposes any late native connection result.

`Remedia.receive(packet)` ignores non-voice packets and voice updates for other
guilds, users, or channels. A voice server/session change starts a fresh OP 4
request and waits for a new state/server pair; dispatch sequence numbers are
used to reject packets older than that request when the client includes them.
The native transport is replaced only after the new credentials arrive. Any
active playback is stopped during replacement; start it again after
`connectionState` returns to `connected`. Voice Gateway WebSocket Resume is
handled inside the native transport and does not send a bot Gateway OP 4.

The application remains responsible for authenticating its Gateway client and
forwarding its raw dispatch packets. The binding does not implement Gateway
connectivity, REST calls, channel commands, or bot authentication. The native
credential-based function is internal to the package; applications do not
collect or pass voice session IDs, tokens, or endpoints. See the
[Discord transport guide](/docs/discord/voice-output) for DAVE support and
protocol limitations.

## Structured diagnostics

Register one callback per `Remedia` instance. Events preserve severity,
tracing target, stable event name, message, structured fields, timestamp in
Unix milliseconds, and optional internal playback/voice correlation IDs.
These IDs are not Discord guild IDs or secret voice session IDs.

```ts
const listener = (event) => {
  console.log(event.severity, event.event, event.playbackId, event.fields);
};
remedia.on('debug', listener);
// Later:
remedia.off('debug', listener);
remedia.removeAllListeners('debug');
```

Media workers do not call JavaScript directly. A dedicated worker forwards one
instance's diagnostic receiver through a bounded
N-API `ThreadsafeFunction`; cloned receivers are not treated as broadcasts.
Events may be dropped under backpressure. `remedia.droppedDebugEvents` reports
drops in both bounded queues. Debug callbacks do not carry operational errors;
those are Promise rejections, playback state, and the `error` properties.
Structured integer fields are strings so `u64` and `i64` values retain full
precision in JavaScript; floating-point fields remain numbers.

Environment variables are read when `Remedia.create()` runs:

| Variable                                         | Default                   | Behavior                                                                                                                       |
| ------------------------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `REMEDIA_DEBUG=1`                                | disabled                  | Enables debug events for Remedia components.                                                                                   |
| `REMEDIA_LOG`                                    | `warn`                    | Tracing filter, for example `remedia_core=info,remedia_discord=debug`; takes precedence over `REMEDIA_DEBUG`.                  |
| `REMEDIA_LOG_FORMAT`                             | `text`                    | Accepts `text` or `json`. Console output is disabled for this embedded binding so the JS callback is not duplicated to stderr. |
| `REMEDIA_OTEL_ENABLED`                           | `false`                   | Set to `true` to enable OTLP traces and metrics.                                                                               |
| `OTEL_SERVICE_NAME`                              | OpenTelemetry SDK default | Service resource name.                                                                                                         |
| `OTEL_RESOURCE_ATTRIBUTES`                       | OpenTelemetry SDK default | Standard resource attributes.                                                                                                  |
| `OTEL_EXPORTER_OTLP_*`                           | HTTP/protobuf defaults    | Standard shared and signal-specific endpoint/protocol settings.                                                                |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | parent-based always-on    | Standard trace sampler configuration, validated when export is enabled.                                                        |

OTLP exporters run asynchronously and are opt-in. `close()` flushes and shuts
down the providers owned by that instance. These bindings do not install or
replace a process-global tracing subscriber, so they can coexist with host
application diagnostics. Core and Discord do not depend on Node.js.

For Rust-level observability setup and metric semantics, see the
[observability guide](/docs/observability/configuration). For the native media
and transport boundaries, see the [decoding guide](/docs/core/decoding) and
the [Discord voice guide](/docs/discord/voice-output).
