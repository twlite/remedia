---
title: Install FFmpeg 9
description: Install the FFmpeg 9 shared libraries Remedia needs, with the official installer or a package manager, and verify the installation.
---

Remedia's native engine decodes audio with **FFmpeg 9** shared libraries (9.0.2). It links them at
runtime and does not bundle them, so FFmpeg 9 must be installed on the machine that runs the engine.

## Recommended: the Remedia installer

The installer provisions FFmpeg 9.0.2 and its shared dependencies. Run the one for your platform:

**Linux and macOS**

```sh
curl -fsSL https://remedia.twlite.dev/install.sh | sh -s -- --ffmpeg-only
```

**Windows PowerShell**

```powershell
& ([scriptblock]::Create((irm https://remedia.twlite.dev/install.ps1))) -FFmpegOnly
```

- FFmpeg is installed to `~/.remedia/ffmpeg9` (`$HOME\.remedia\ffmpeg9` on Windows), outside your system library directories. Your system FFmpeg is not replaced.
- `@remedia/node` finds that directory automatically. You do not need to set `PATH`, `LD_LIBRARY_PATH`, or any other variable.
- `--ffmpeg-only` / `-FFmpegOnly` installs **only FFmpeg**. It does not install `remedia-server`, does not add commands, and does not edit your shell profile or `PATH`. You can run it again to update or re-verify FFmpeg.
- The installer downloads FFmpeg from conda-forge, so it needs network access. Set `REMEDIA_INSTALL_DIR` to install under a different prefix.

<Callout title="Note">
  You only need one installation method. The manual installation methods below are alternatives, not
  additional steps.
</Callout>

Supported installer platforms: Linux x64 and ARM64 (glibc), macOS Intel and Apple Silicon, and
Windows x64.

## Where FFmpeg is needed

| Mode                                                                 | FFmpeg location                       |
| -------------------------------------------------------------------- | ------------------------------------- |
| Embedded (`@remedia/node`, or an embedded node in `@remedia/client`) | The machine running your Node.js bot  |
| Remote (`remedia-server`)                                            | The machine running `remedia-server`  |
| Remote-only client (`@remedia/client` with only remote nodes)        | No local FFmpeg installation required |

If you are installing the full Remedia server, follow [Install the server](/docs/server/installation)
instead: its default mode installs FFmpeg and the server together.

## Verify the installation

Run this from the directory of your project, after installing `@remedia/node`:

```sh
node --input-type=module -e "import { Remedia } from '@remedia/node'; const engine = await Remedia.create(); await engine.close(); console.log('Remedia native runtime OK')"
```

It prints `Remedia native runtime OK` when the native addon loads and initializes. It does not test
decoding or Discord voice. To see which FFmpeg installation was loaded:

```ts
import { getFfmpegRuntime } from '@remedia/node';

const runtime = getFfmpegRuntime();
console.log(runtime.source, runtime.directory);
```

For a server, run [`remedia-server doctor`](/docs/server/cli#diagnose-the-server) on the audio host.
If loading fails, the error lists every location that was tried and why each was rejected; see
[native library troubleshooting](/docs/node/troubleshooting).

## Manual installation

Use these only if you do not want the installer. After installing, run the verification above.

### macOS

Homebrew's `ffmpeg` formula is FFmpeg 9.0.2 (also available as `ffmpeg@9`):

```sh
brew install ffmpeg
```

`@remedia/node` finds Homebrew's installation under `/opt/homebrew` (Apple Silicon) or `/usr/local`
(Intel) automatically. Your Node.js architecture and FFmpeg architecture must match. As an alternative,
micromamba can install a pinned build:

```sh
micromamba create -n remedia-ffmpeg9 -c conda-forge 'ffmpeg=9.0.2'
micromamba activate remedia-ffmpeg9
export REMEDIA_FFMPEG_DIR="$CONDA_PREFIX"
```

### Windows

Install a **shared** FFmpeg build. Static builds do not provide the DLLs Remedia loads.

- **Scoop** (`ffmpeg-shared` is the gyan.dev shared build, 9.0.2). Scoop adds its `bin` directory to your `PATH`, which `@remedia/node` searches:

  ```powershell
  scoop install ffmpeg-shared
  ```

- **Winget** (`Gyan.FFmpeg.Shared`, 9.0.2). Winget only creates command aliases for `ffmpeg.exe`; the DLLs are not added to `PATH`. Point Remedia at the package's `bin` folder:

  ```powershell
  winget install Gyan.FFmpeg.Shared
  $env:REMEDIA_FFMPEG_DIR = "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\Gyan.FFmpeg.Shared_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-9.0.2-full_build-shared\bin"
  ```

  The package folder name can differ on your machine. Locate the directory containing `avcodec-63.dll` and use that path.

- **Manual download:** the "full_build-shared" archive from [gyan.dev](https://www.gyan.dev/ffmpeg/builds/). Extract it and set `REMEDIA_FFMPEG_DIR` to its `bin` folder, or add that folder to `PATH`.
- **micromamba:**

  ```powershell
  micromamba create -n remedia-ffmpeg9 -c conda-forge ffmpeg=9.0.2
  micromamba activate remedia-ffmpeg9
  $env:REMEDIA_FFMPEG_DIR = $env:CONDA_PREFIX
  ```

You may also need the matching [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist).

### Linux

Remedia needs the **glibc** build of FFmpeg 9 shared libraries. As of November 2026, most stable
distributions still ship older majors, so check before using your package manager:

| Distribution                                    | FFmpeg in the stable repositories             |
| ----------------------------------------------- | --------------------------------------------- |
| Arch Linux, Manjaro                             | 9.0.2: `sudo pacman -S ffmpeg`                |
| Debian 13, Ubuntu 24.04 / 26.04, Fedora 43 / 44 | Older than 9; use the installer or micromamba |
| Debian testing/unstable, Fedora Rawhide         | 9.0.2 only in development releases            |

On a distribution with FFmpeg 9 packaged, install it with the package manager and `@remedia/node`
finds it in the loader's standard directories. Do not mix unstable or development repositories into a
stable system just to get FFmpeg 9; use the Remedia installer or micromamba instead:

```sh
micromamba create -n remedia-ffmpeg9 -c conda-forge 'ffmpeg=9.0.2'
micromamba activate remedia-ffmpeg9
export REMEDIA_FFMPEG_DIR="$CONDA_PREFIX"
```

If your platform has no FFmpeg 9 package, build FFmpeg 9.0.2 from source with shared libraries
(`./configure --enable-shared`), and make sure the libraries, headers and runtime loader paths all
describe the same build.

## Advanced

### How `@remedia/node` chooses an installation

Importing `@remedia/node` selects FFmpeg before the engine loads. Nothing is downloaded and no
environment variable is changed. The first usable installation in this order wins:

1. **`REMEDIA_FFMPEG_DIR`**, when set. It names an installation prefix (for example `~/.remedia/ffmpeg9`) or its library directory (`lib` on Linux and macOS, `Library\bin` or `bin` on Windows). If it cannot be loaded, the import fails and no other installation is tried.
2. **A system installation**: the directories your platform's loader searches, including `LD_LIBRARY_PATH` and standard library directories on Linux, `DYLD_*` paths and Homebrew's prefixes on macOS, and the Node.js directory plus `PATH` on Windows. The current directory is never searched.
3. **The installer-managed prefix** `~/.remedia/ffmpeg9`.
4. Otherwise an `FfmpegLoadError` listing every path considered.

An installation is accepted only if all five libraries are present at the right versions, match the
process architecture, resolve their own dependencies, and live in the same directory.

### Required library versions

| Library       | ABI major | Linux / FreeBSD      | macOS                   | Windows            |
| ------------- | --------- | -------------------- | ----------------------- | ------------------ |
| libavcodec    | 63        | `libavcodec.so.63`   | `libavcodec.63.dylib`   | `avcodec-63.dll`   |
| libavformat   | 63        | `libavformat.so.63`  | `libavformat.63.dylib`  | `avformat-63.dll`  |
| libavutil     | 61        | `libavutil.so.61`    | `libavutil.61.dylib`    | `avutil-61.dll`    |
| libavfilter   | 12        | `libavfilter.so.12`  | `libavfilter.12.dylib`  | `avfilter-12.dll`  |
| libswresample | 7         | `libswresample.so.7` | `libswresample.7.dylib` | `swresample-7.dll` |

Older or newer majors cannot be substituted by renaming files or creating symlinks. To check a
`pkg-config` installation, `pkg-config --modversion libavcodec libavformat libavutil libavfilter libswresample`
should report majors 63, 63, 61, 12 and 7.

### The standalone server runtime

`remedia-server` starts its native runtime through the `remedia` launcher installed by the Remedia
installer, which configures library paths. If you provide FFmpeg yourself (installer option
`--no-ffmpeg` / `-NoFFmpeg`), the runtime relies on the system loader, so make the FFmpeg directory
visible to the process: `LD_LIBRARY_PATH` on Linux, `DYLD_LIBRARY_PATH` on macOS, or `PATH` on
Windows. Run `remedia-server doctor` to confirm.

### Building Remedia from source

Compiling Remedia (not running a published addon) needs FFmpeg 9 headers and `pkg-config` metadata.
Set `FFMPEG_DIR` to the FFmpeg prefix and `PKG_CONFIG_PATH` to its `lib/pkgconfig` directory so the
build links FFmpeg 9 and not another version on your machine. These variables only affect builds;
they are not read when a published package runs. See
[CONTRIBUTING.md](https://github.com/twlite/remedia/blob/main/CONTRIBUTING.md) and
[`verify-native-deps.mjs`](https://github.com/twlite/remedia/blob/main/.github/scripts/verify-native-deps.mjs).

### Other targets

FreeBSD x64 is tested against a pinned FFmpeg 9.0.2 source build. Linux musl, ARMv7 and Android
targets are cross-compiled in CI but are build-only; they carry no runtime compatibility
guarantee. See [package distribution](/docs/node/distribution) for platform coverage.

### Inspecting a native addon

Use `ldd` (Linux, FreeBSD), `otool -L` (macOS) or `dumpbin /DEPENDENTS` (Windows) to see which
FFmpeg libraries an addon requests. On macOS, the published addon requests
`@rpath/libavcodec.63.dylib` and so on, which lets `@remedia/node` choose among Homebrew, the managed
prefix and `REMEDIA_FFMPEG_DIR`; a custom build whose libraries carry absolute install names elsewhere
cannot be selected. Licensing implications of redistributing FFmpeg are in [licensing](/docs/licensing).
