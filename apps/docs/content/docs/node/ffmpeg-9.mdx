title: Bundled FFmpeg 9
description: Static FFmpeg builds, diagnostics, and distribution terms.
---

Official native addons and server runtimes statically link FFmpeg 9.0.2. Installing
FFmpeg, micromamba, or configuring library search paths is unnecessary. System
FFmpeg installations are not selected by the addon. Source builds need the pinned
native build recipe in `.github/scripts/build-ffmpeg-static.sh` (POSIX) or the
pinned vcpkg manifest in `.github/native-deps/windows-cross` (Windows).

## Inspect the bundle

```ts
import { getFFmpegRuntime } from '@remedia/node';

const info = getFFmpegRuntime();
console.log(info.source); // bundled
console.log(info.version, info.license, info.configuration);
console.log(info.remediaVersion, info.remediaCommit);
console.log(info.libraries);
```

`directory` is null, `considered` is empty, and each library `path` is empty because
there are no separate library files. The metadata API is `getFFmpegRuntime()` (renamed after v0.3.0).
The server exposes equivalent build information through `remedia --version` and
`remedia doctor`; doctor also checks library ABI capabilities and configuration.
The metadata comes from the linked FFmpeg API, including the configure command.

## Licensing and source

Remedia's original source remains MIT. FFmpeg-independent packages remain MIT.
Native addon packages declare `SEE LICENSE IN LICENSES.md`; statically combined
addons and server runtimes are distributed subject to GPLv3-or-later obligations.
See `LICENSES.md`, `COPYING.GPLv3`, and the third-party acknowledgments distributed
with the packages and installed alongside server executables.

Complete corresponding source is retrieved using the exact binary version, as
explained in `SOURCE_DISTRIBUTION.md` included with native npm packages; server archives carry retrieval directions in
`LICENSES.md`. The binary release's `source-manifest.json` names the Remedia revision,
hash-verified release source archive and target configurations, and a public,
content-addressed dependency snapshot. Shared snapshots are hosted on this
repository's source-only GitHub releases and reused when inputs match. The
release-specific source archive ships with the regular public GitHub release.
Both source parts are available before npm publication; no upstream clone is required.
The original v0.3.0 source archive remains unchanged.

This implements equivalent network source access under GPLv3 §6(d). Source must
remain available while the binaries are distributed. Redistributors must meet
applicable source, notice and installation-information obligations. Automated
checks do not establish legal compliance. See the
[GPLv3 text](https://www.gnu.org/licenses/gpl-3.0.html) and
[FFmpeg licensing information](https://ffmpeg.org/legal.html).

## Target verification

The existing 13 addon targets are retained. Linux GNU, macOS and Windows x64/ARM64
run the native test matrix on Node 22.18, 24 and 26. Linux musl x64/ARM64 load and
decode in clean Alpine containers, and FreeBSD x64 runs native tests in a VM.
Android, Linux ARMv7 and Windows x86 addons have build and linking checks but
remain experimental until native runtime validation succeeds. The musl smoke
checks provide narrower playback coverage than the full native test matrix.
System C runtimes, OS frameworks and certificate stores may still be required;
static FFmpeg linking does not mean every OS dependency is statically linked.
